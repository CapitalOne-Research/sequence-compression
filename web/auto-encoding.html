Auto Encoding

Mark a feature as auto and seqpack searches for the smallest pipeline for each user's sequence on its own. One column can end up with several different pipelines, each matched to the shape of that user's data.

§ 00.

One flag per feature

Picking a pipeline by hand means choosing one answer for every user in a column. User behaviour isn't that uniform: one user never likes anything, another likes a few videos back to back, a third likes scattered videos all through their history.

With auto, the choice moves from the column to the row. For each user's sequence, seqpack tries every valid combination of schemes up to three steps deep, measures the encoded bytes, and keeps the smallest. If nothing beats the raw sequence, the row is stored unencoded.

Every encoded row records the pipeline it used, so decoding needs no per-column configuration: decode_feature_payload reads the pipeline name from each entry and reverses it. 

from seqpack import encode_feature_df, decode_feature_payload

encoded = encode_feature_df(df, {
    "is_like": "auto",
    "date":    "auto",
    "tab":     "auto",
})

# each row stores [value, pipeline, aux]

Pipelines above are from the is_like column of the demo dataset.

    Per user beats one size fits all

    § 03.

    How auto searches

    1. Detect the element type of the sequence: binary, integer, float or string.
    2. Try every scheme that accepts that type, then every scheme that accepts what it outputs, up to three steps deep. A step that looks larger on its own is still explored: cat alone grows a sequence, but cat_rle_bp can shrink it a lot.
    3. Steps that write metadata (cat, del, stl, quant) appear at most once. Packers (bm, bp, nbp) output a bitstream, so they can only be the last step.
    4. Measure each candidate as it would be stored, including the pipeline name and its metadata, and keep the smallest.
    5. If no pipeline beats the raw sequence, keep the raw sequence.
